# Zoom overlays — sources

Two specs, generated by `scripts/generate_app_overlays.py`; `fetch_icons.py`
rebuilds `icons/` except the reclaimed ones.

| Spec | Set | Loads for |
|---|---|---|
| `bindings.yaml` | `zoom_template` (2 files), `_mac` (4 files) | the meeting and webinar windows ("Zoom Meeting", "Zoom Webinar"), and a window whose title is unknown |
| `main.yaml` | `zoom_main_template` (2 files), `_mac` (3 files) | the main window, "Zoom Workplace": chat, Zoom Phone and the general keys |

The mapping's `title` gate keeps Zoom's other windows (settings, a pop-out chat)
out, as before. App names: the 7.2.1 Linux client, run under Xvfb on 2026-10-22,
reports the process `zoom`, WM_CLASS `zoom` and the main window title "Zoom
Workplace". "Zoom Meeting" and "Zoom Webinar" are in the binary as plain
strings; the German and Russian translation files do not translate them. macOS
reports `zoom.us`. The meeting window itself was not opened (it needs a
meeting).

## Shortcut references

- Zoom Support, "Using hot keys and keyboard shortcuts" (KB0067050, revision
  2026-07-01), <https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0067050>,
  read 2026-10-22 with headless Chromium (the page is drawn by JavaScript; it
  was unreachable when the first overlay was built). Its Windows and Linux tabs
  list the same 24 keys; its macOS tab lists about 80, in Meeting, Chat, Clips,
  Phone and General sections.
- The first overlay (2026-06) used search-result excerpts of an older revision
  and university pages (UW Accessible Technology, BYU, Harvard HUIT). Five of its
  Windows/Linux keys are not in the current Windows tab: Alt+H (chat panel),
  Alt+F (full screen), Alt+Q (end meeting), Alt+F1 and Alt+F2 (speaker and
  gallery view). They stay, marked here, until a Zoom client shows otherwise.

Zoom's Linux tab matches its Windows tab (Alt+letter), so they share one set.
Note GNOME binds Alt+F1/Alt+F2 itself, which may shadow Zoom's view keys there.

## macOS is a REMAP, not a CMDCTRL swap

Every macOS line is written with literal mods and `only: [macos]`; every
Windows/Linux line with `only: [windows, linux]`. The spec uses no `CMDCTRL`, so
the generator renders its macOS set because bindings name `macos` in `only:`
(`spec_needs_macos_set`).

**End / leave meeting has no Mac cell.** Older third-party copies of Zoom's list
put "Prompt to End or Leave Meeting" on ⌘W, but the current Zoom article
(KB0067050) lists ⌘W only under *General*, as "Close current window", and names
no Mac chord for the end/leave prompt. A chord the current source does not
confirm is not drawn.
Reserved-chord check: ⌘T is Zoom's own in-meeting binding; no ⌘H, ⌘M, ⌘Q, ⌘W,
⌘Tab or ⌘Space.

## Skipped

- Alt (bare) — always-show-controls on Windows: no cell for a lone modifier.
- Ctrl+Alt+Shift (focus meeting controls), F6 (cycle popups), Space (push to
  talk), Ctrl+2 (read speaker name), Alt+F4: no cell, or not meeting-specific.

## Standard editing shortcuts (shared Fluent concepts, 2026-10-08)

Label = lexicon concept, no icon.

| Concept | Windows / Linux | macOS | Source |
|---|---|---|---|
| Close | (already drawn: Ctrl+W "Close chat") | ⌘W, `only: [macos]` | Zoom KB0067050, macOS *General*: "Command+W: Close the current window"; confirmed by search excerpts of university copies (GVSU, Roane State, City of Santa Barbara) |

Not added / why: the mapping is title-gated to the meeting window, and Zoom
documents none of Save / Open / New / Print / Cut / Copy / Paste / Undo / Redo /
Select all / Find / Zoom / Reload as in-meeting chords. Zoom is not an Electron
app, so no editing roles are assumed.
