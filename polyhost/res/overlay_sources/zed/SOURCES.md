# Zed overlay: sources and licences

## Folder layout (two files more than usual, on purpose)

Besides the usual `bindings.yaml`, `fetch_icons.py`, `SOURCES.md` and `icons/`,
this folder holds `derive_bindings.py` and `derive_table.yaml`. Zed ships three
JSON keymaps, and `bindings.yaml` is GENERATED from them so a Zed update is a
re-run, not a hand edit. `derive_table.yaml` holds the hand-chosen parts (label
and icon per action, skip lists), so they survive a regeneration. The generator
stays beside its output, as `gen_blender_bindings.py` does for Blender.

## Shortcuts

Authority: Zed's own default keymaps, read from source at
**zed-industries/zed @ `36682547bea1c3d4fa60c08d341cf60081853941`** (2026-10-13):

- `assets/keymaps/default-windows.json` (`w` in each binding's `source:`)
- `assets/keymaps/default-linux.json` (`l`)
- `assets/keymaps/default-macos.json` (`m`)

Each binding's `source:` gives the Zed action and the line in each keymap that
binds it, e.g. `workspace::Save @ w656 l660 m718`.

### Why one spec with `only:` scopes, not `CMDCTRL` alone

Measured over the drawable cells of the contexts below, with Cmd normalised to Ctrl:

| pair | same action | same chord, different action | actions on a disjoint chord set |
|---|---|---|---|
| Linux vs macOS | 113 | **32** | **75 of 183** |
| Windows vs macOS | 107 | 30 | 79 of 181 |
| Windows vs Linux | 184 | 6 | 19 of 191 |

The macOS keymap is a different keymap, not a modifier swap. Examples: tab N is
Alt+N on Windows/Linux and Ctrl+N on macOS, while Cmd+N on macOS is *pane* N.
Fold/Unfold is Ctrl+Shift+[ / ] vs Cmd+Alt+[ / ]. Ctrl+Shift+Up/Down is select
previous/next occurrence on Linux, but select to paragraph start/end on macOS.
Windows and Linux also differ, because Linux avoids Alt+letter: Format is
Alt+Shift+F on Windows and Ctrl+Shift+I on Linux; Go back is Alt+- / Alt+Left on
Windows and Ctrl+Alt+- on Linux.

So, as with `../zoom/`, every binding is derived mechanically from the three
keymaps and scoped to the platforms that bind it. A binding uses `CMDCTRL` only
when the same action sits on Ctrl+X on Windows or Linux AND on Cmd+X on macOS.
Otherwise it uses literal modifiers. The generator therefore emits three sets:
`zed_template` (Windows, the default), `zed_linux_template` and
`zed_mac_template`. Each set holds exactly one platform's keymap: no cell borrows
another platform's chord.

### Regenerating `bindings.yaml`

`bindings.yaml` is GENERATED by `derive_bindings.py`. That script applies the
rules below to the three keymaps. The hand-chosen parts come from the committed
`derive_table.yaml`: contexts and their depths, skipped actions, and each action's
group, label and icon. The file header also lives in that table. Edit the table,
never the output. Run from the repo root:

```bash
git clone --filter=blob:none --sparse https://github.com/zed-industries/zed <zed>
git -C <zed> checkout 36682547bea1c3d4fa60c08d341cf60081853941
git -C <zed> sparse-checkout set assets/keymaps
.venv/bin/python polyhost/res/overlay_sources/zed/derive_bindings.py <zed>
.venv/bin/python polyhost/res/overlay_sources/zed/fetch_icons.py
PYTHONPATH=. .venv/bin/python scripts/generate_app_overlays.py \
    polyhost/res/overlay_sources/zed/bindings.yaml --preview /tmp/zed_preview
```

At the pinned commit this reproduces `bindings.yaml` byte for byte, and the
generator then reproduces the same PNGs (sha256-checked). If Zed adds an action
the table lacks, the script stops and lists the action. Add it to `actions:` or
`skip:` in the table. The glyph behind an icon file (for example `enclosingsymbol`
= Fluent `Code Block`, chosen so it does not draw the same `{x}` as Signature
help) is set in `fetch_icons.py`.

### Which bindings are drawn (derivation rules)

1. **Contexts.** The drawn contexts are: global (no context), `!Terminal`,
   `!SettingsWindow`, `Workspace`, `Workspace && !Terminal`, `Pane`, `Editor`, and
   `Editor && mode == full`. Panel-only, picker, modal, terminal, agent,
   git-panel, notebook and settings-window contexts are skipped. Vim and Helix
   modes are separate keymaps (`vim.json`) and were not read. The base-keymap
   presets (`linux/`, `macos/` subfolders: VS Code, JetBrains, Sublime, Emacs and
   others) are opt-in and were not read either.
2. **Precedence follows Zed.** The deeper context wins (Editor > Pane > Workspace >
   global). Within one depth, the later block wins, and `null` unbinds. Examples:
   Alt+1 is `pane::ActivateItem 0` (Pane) rather than `workspace::ActivatePane 0`
   (Workspace) on Windows/Linux. Ctrl+Alt+- on Linux is Go back (Pane), not
   shrink-dock (Workspace).
3. **Debugger-state blocks fill gaps only.** These are `Workspace && debugger_stopped`,
   `debugger_session` and `debugger_running`. A debugger chord is drawn only on a
   cell that no always-active binding uses. So F5/F6/F10/F11 keep their idle
   meaning (rerun debug session, focus next part, application menu, fullscreen).
   Shift+F5 (stop), Ctrl+Shift+F5, F7, Ctrl+F11 and Shift+F11 show their debugger
   meaning, because nothing else uses those keys. On macOS F10 and F11 are free
   (fullscreen is Cmd+Ctrl+F), so they show step over / step into there.
4. **Not drawable:**
   - two-stroke chords (`ctrl-k ctrl-s` and the like);
   - Escape (the program-mark cell);
   - media keys (`copy`, `paste`, `find`, `back`, ...);
   - `fn-f`.
5. **Shifted punctuation is the US-layout key plus Shift.** `ctrl-{` = Ctrl+Shift+[,
   `ctrl-?` = Ctrl+Shift+/, `ctrl-~` = Ctrl+Shift+`, `ctrl-alt-_` = Ctrl+Alt+Shift+-.
6. **Skipped actions (186 chords across the three keymaps):**
   - Cursor and text-field primitives that every text box has: `editor::Move*`,
     `Select{Up,Down,Left,Right}`, `SelectTo*`, `SelectPage*`, `LineUp/Down`,
     `PageUp/Down`, `Newline`, `Tab`/`Backtab`, `Backspace`/`Delete`, and
     word/subword/line delete and motion.
   - The macOS Cocoa/Emacs text-system bindings: Ctrl+A/E/N/P/B/F/H/D/W/V/L,
     KillRing Ctrl+K/Y, Transpose Ctrl+T.
   - `menu::*` and `picker::*`: active only while a menu or picker is open.
   - `dev::*`: inspector and FPS overlay.

Result: **279 binding lines**. Placed cells (program mark included): **171 Windows,
180 Linux, 191 macOS**. All four tiers are used. On Windows the gui tier holds a
single cell: Ctrl+Alt+Super+P, the settings profile.

## Icons

- **Borrowed byte-identical** (`icon_fetch.borrow`) wherever another editor overlay
  already draws the same action:
  - `../vscode`: quickopen, gotosymbol, rename, definition, explorer,
    extensions, debugview, problems, terminal, findinfiles, replaceinfiles,
    sidebar, split, history.
  - `../sublime`: commandpalette, gotosymbolproject, gotoline, reopentab,
    blockcomment, deleteline, swapup/down, joinlines, insertafter/before,
    fold/unfold, selectline, multicursor, selectalloccur, cursorabove/below,
    matchbracket, autocomplete, gotoword, duplicate.
  - `../jetbrains`: extendselection, shrinkselection, optimizeimports,
    paraminfo, intentions, rerun, win_git. Its reclaimed whole-cell drawings are
    also borrowed: back, forward, breakpoint, debug, findusages,
    gotodeclaration, gotoimpl, gototypedecl, reformat, stepinto/out/over and stop.
    These are bound with JetBrains' own `region: [72, 40], anchor: center`, so
    the cells match.
  - `../windowsterminal`: newwindow, settingsfile, tab.

  Provenance and licences (Fluent MIT, custom editor glyphs) are as recorded in
  those folders' SOURCES.md.
- **Microsoft Fluent UI System Icons (MIT)**, the house style:
  <https://github.com/microsoft/fluentui-system-icons>. The `FLUENT` map in
  `fetch_icons.py` names the glyph for each file.
- **Google Material Symbols (Apache-2.0, GPLv3-compatible)** for the gaps:
  `manage_search`, `regular_expression`, `swap_horiz`, `difference`,
  `unfold_more`, `format_list_numbered`.
- **Composites**, drawn in `fetch_icons.py` (`_badge`) and guarded. Each one takes
  a glyph above, shrinks it to the lower left, and adds a small badge top right:
  - an up or down triangle, for the previous/next member of a pair
    (diagnostic, hunk, change, occurrence, syntax node, find, duplicate line);
  - left/right, for previous/next tab;
  - a split pane, for the "(split)" go-to variants;
  - a plus, for new terminal;
  - a cross, for close window and close other tabs.

  Zed binds many such pairs, and two keys of one app must not draw the same
  picture for different actions.

  `tabmoveright` is `tabmoveleft` mirrored. `tablast` is the tab glyph with `»`.
- **Numbered tabs and panes** (`../number_badge.py`):
  - `tab1..9` are numbers over Windows Terminal's tab glyph (tab1..8 are
    byte-identical to Windows Terminal's).
  - `pane1..9` are numbers over Fluent `Window`, which has a title bar, so pane N
    and tab N look different on macOS, where both exist.
- **Labels the lexicon names** (Save, Save as, New, Open, Quit, Hide, Minimize,
  Fullscreen, Settings, Zoom in/out/reset, Close, Find, Replace, Find next, Copy,
  Cut, Paste, Undo, Redo, Select all, Indent, Outdent, Comment) are drawn by the
  shared concept renderer (84 cells over the three sets). There is no file in
  `icons/` for them.

## Program mark (ESC)

`icons/zed.png` is **Zed's own app icon**, taken from
`crates/zed/resources/app-icon.png` at the pinned commit. The licence was checked
before it was used:

- The `zed` crate declares `license = "GPL-3.0-or-later"` (`crates/zed/Cargo.toml`)
  and ships `LICENSE-GPL`.
- The README says the source is "licensed primarily under GPL-3.0-or-later, with
  Apache-2.0 components where marked".
- No asset, logo or trademark carve-out exists for `crates/zed/resources/`.
  `legal/trademarks.md` returns 404, and the README has no logo clause.

GPL-3.0-or-later matches this host's licence, so the icon is redistributed under
it. The name and logo may still be trademarks of Zed Industries; that is the same
position as the other free-software marks shipped here (WinSCP, PuTTY, 7-Zip).

Transform (in `fetch_icons.py`, guarded): `fetch_icons.py` crops the icon to its
light linework plus 12% padding. The tile's own padding would otherwise shrink
the mark to about 22 px on a 40 px cell.

Render settings, picked by sweeping at keycap size:

- **`program_icon_mode: bright`**, because the icon is a dark tile carrying light
  linework. `alpha` lights the whole tile as one blob, and `luma` inverts it.
- **Threshold 110**. Thresholds from t70 to t160 were tried: t70 to t90 fill the
  nested frames, and t130 and above break the Z diagonal.
- **Region `[46, 40]`, anchored right**, with 0 margin.

Preview and Nightly ship differently coloured icons (`app-icon-preview.png`,
`app-icon-nightly.png`). All channels use the same stable mark here.

## Window matching

- **Windows:** the installer ships `Zed.exe` for every channel
  (`script/bundle-windows.ps1`: `$appExeName = "Zed"`), so the key is `zed`.
- **macOS:** the bundle names are `Zed`, `Zed Preview`, `Zed Nightly` and
  `Zed Dev` (`crates/zed/Cargo.toml` `[package.metadata.bundle-*]`), so the keys
  are the lowercased names.
- **Linux:** the GUI binary is `libexec/zed-editor` (`script/bundle-linux`;
  `bin/zed` is only the CLI), so X11 process-name lookup gives `zed-editor`. The
  Wayland and X11 app id / WM_CLASS is `dev.zed.Zed` (or `-Preview`, `-Nightly`,
  `-Dev`) from `ReleaseChannel::app_id()` in `crates/release_channel/src/lib.rs`,
  which is also the `.desktop` file name. All of these are listed lowercased.
