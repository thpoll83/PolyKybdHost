# QGIS overlays — sources

One spec (`bindings.yaml`) writes three sets, generated by
`scripts/generate_app_overlays.py`; `fetch_icons.py` rebuilds `icons/`.

| Set | Loads for | Keys |
|---|---|---|
| `qgis_template` (3 files) | Windows: `qgis-bin.exe`, `qgis-ltr-bin.exe`, `qgis-dev-bin.exe`, `qgis-qt6-bin.exe` | 91 + ESC mark |
| `qgis_template_linux` (3 files) | Linux: `qgis`, `qgis3`, `qgis4`, `org.qgis.qgis`. Without Ctrl+Alt+T | 90 + ESC mark |
| `qgis_template_mac` (4 files) | macOS: "QGIS", "QGIS-LTR" | 87 + ESC mark |

## App names (routing)

Read from the QGIS source at final-4_2_3, not checked on an install:

- `CMakeLists.txt`: `QGIS_APP_NAME` is `qgis`, the executable name on every
  platform and the macOS `CFBundleExecutable`.
- `platform/macos/Info.plist.in`: `CFBundleName` is `QGIS`. The official macOS
  packages are built in a separate repository; the LTR is installed as
  `QGIS-LTR.app`, so "QGIS-LTR" is listed as well. Both macOS names are
  unverified.
- `linux/org.qgis.qgis.desktop.in`: `Exec=qgis`, `StartupWMClass=QGIS4`.
  `src/core/qgsapplication.cpp` sets the application name to `QGIS4` (4.x) and
  `QGIS3` (3.44), which Qt uses as the X11 WM_CLASS class; the GNOME and KDE
  reporters return that name. `src/app/main.cpp` sets the desktop file name
  `org.qgis.qgis` on Wayland, which is the Wayland app id and the Flatpak id.
- Windows: OSGeo4W and the standalone installer start `qgis-bin.exe`
  (`qgis-ltr-bin.exe` for the LTR, `qgis-dev-bin.exe` for the nightly,
  `qgis-qt6-bin.exe` for the Qt 6 test builds of 3.x). These names come from the
  OSGeo4W packaging, not from the QGIS repository, and are unverified.

The layout designer, the model designer, the attribute table and the 3D view
can be separate windows of the same process. They load this set too; it shows
the main window's keys.

## Shortcut reference

QGIS's source, read 2026-11-07, at tag **final-4_2_3** (4.2.3, commit
b041a18904a4dc9fdada8ecb2c84385054ddfee1), the current release. The current LTR,
**final-3_44_15** (3.44.15), was compared: it has the same keys except four
that are new in 4.x: Ctrl+Alt+E (new elevation profile), Ctrl+Shift+E (set 3D
scene extent) and Ctrl+Shift+[ / ] (nudge the 3D cross section). On 3.44 those
four keys do nothing.

- `src/ui/qgisapp.ui`: every `shortcut` property (52 actions).
- `src/app/qgisapp.cpp`: the QShortcuts (Ctrl+0..9 panels, Ctrl++/Ctrl+=,
  Ctrl+-, Ctrl+Alt+=, Ctrl+K, F12), `setShortcut` (F7, and the macOS changes
  below), the six `registerShortcuts` application shortcuts
  (Ctrl+Alt+{ [ ] } , .), the three 3D ones, Copy/Cut/Paste/Select All on the
  map canvas and layer tree, and Delete/Backspace on the canvas (delete
  selected features).
- `src/app/qgssnappingwidget.cpp` (S snapping, T tracing) and
  `src/app/maptools/qgsmaptoolsdigitizingtechniquemanager.cpp` (R stream
  digitizing).
- `src/gui/qgsmapcanvas.cpp` `keyPressEvent`: PgUp/PgDn zoom, Space pan.
- `python/plugins/processing/ProcessingPlugin.py` (a core plugin, on by
  default): Ctrl+Alt+T toolbox, Ctrl+Alt+G model designer, Ctrl+Alt+H history,
  Ctrl+Alt+R results viewer.

The QGIS user manual (Configuring QGIS, Keyboard shortcuts) describes the
shortcut editor but has no list.

Qt reads "Ctrl" as Cmd on macOS, so every Ctrl key is Cmd there. A key written
with a shifted symbol ("Ctrl+Alt+{") is drawn on the US key that types it, with
Shift added.

Platform differences in the set:

- macOS: `qgisapp.cpp` moves Help from F1 to Cmd+? (drawn on Cmd+Shift+/) and
  clears the home-page key (Ctrl+H). Cmd+Tab and Cmd+Shift+Tab (Toggle panels,
  Toggle map only) and Cmd+Option+H (Processing history) are taken by the
  system. Backspace is drawn as Delete as well as Del.
- Linux: Ctrl+Alt+T opens a terminal on the GNOME and KDE desktops, so the
  Processing toolbox key is left out there.

### Left out

- Esc (stop rendering): the ESC key carries the program mark.
- Arrow keys (pan the map): the keycap legend already shows the direction.
- The shifted spellings of keys already drawn: Ctrl++ (Ctrl+Shift+=, zoom in)
  and Ctrl+Alt++ (Ctrl+Alt+Shift+=, zoom in tool).
- Ctrl+Shift+. (event tracing): a debugging key that does nothing until a
  setting in Options > Advanced is enabled.
- macOS Cmd+M: `qgisapp.cpp` gives it to Minimize and the .ui to New Map View,
  so the key is ambiguous there. On Windows and Linux Ctrl+M is New Map View
  (the second Ctrl+M action in the .ui, `actionActionCatchForCustomization`, is
  not added to any menu or widget, so it does not fire).
- The Advanced Digitizing keys (X, Y, Z, M, A, D, C, P, N and their Shift
  variants): they work only while the Advanced Digitizing tools are on during
  digitizing; outside that the same letters do nothing.
- Keys of separate windows and dialogs: the layout designer, the model
  designer, the 3D view (Ctrl+0, Ctrl+Shift+D), the attribute table dialog
  (Ctrl+J, Ctrl+P, Ctrl+F, Del there), the code editors and the DB Manager.

## Icons

- Microsoft Fluent UI System Icons, MIT,
  <https://github.com/microsoft/fluentui-system-icons>.
- Material Symbols, Apache-2.0, <https://fonts.google.com/icons>: every `ms:`
  entry in `fetch_icons.py`.
- Copied byte-identical (`icon_fetch.borrow`) where the action is the same:
  `snap.png` (Blender, drawn magnet), `fullscreen.png`,
  `refresh.png`, `console.png`, `isometric.png`, `storeview.png`,
  `recallview.png` (FreeCAD), `measure.png`, `zoomfit.png`, `unselectall.png`,
  `search.png`, `togglelayer.png` (KiCad). Their sources are in those sets'
  SOURCES.md.
- Text in DejaVu Sans Bold, drawn in `fetch_icons.py`: PG, ORA, SL, WMS, CSV,
  GPKG (the layer types) and ε (QGIS's expression symbol).
- `zoomintool.png` and `zoomouttool.png` (Ctrl+Alt+= / Ctrl+Alt+-) are
  `ms:zoom_in_map` / `ms:zoom_out_map` with a + or - drawn in the middle by
  `fetch_icons.py` (`_add_sign`), so the two keys read apart.
- New, Open, Save, Save As, Quit, Undo, Redo, Cut, Copy, Paste, Select All,
  Delete, Zoom In, Zoom Out and Help are drawn by the shared concept renderer.

### ESC mark (`icons/qgis.png`)

QGIS's own monochrome logo, `images/icons/qgis-icon-minimal-black.svg` at
final-4_2_3 (the file QGIS ships for its "image" map decoration). Its QGIS
SVG-marker parameters are resolved (black fill, no outline); the shapes are not
changed. It is rendered at 32x32 with cairosvg and every pixel with alpha 128 or
more is lit. Drawn at the keycap size so the generator copies it 1:1.
`fetch_icons.py` leaves a committed `qgis.png` as it is.
