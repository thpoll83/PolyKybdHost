# Audacity overlays — sources

`gen_specs.py` holds one table and writes three specs from it; each spec is
generated by `scripts/generate_app_overlays.py`; `fetch_icons.py` rebuilds
`icons/`.

| Spec | Set | Loads for |
|---|---|---|
| `audacity3.yaml` | `audacity3_template` (3 files) | Windows, `Audacity.exe` (3.x) |
| `audacity4.yaml` | `audacity4_template` (3 files) | Windows, `Audacity4.exe` (4.x) |
| `audacity.yaml` | `audacity_template` (2 files), `_mac` (3 files) | Linux and macOS, "Audacity" |

Audacity 4 has a new shortcut system and a different keymap. On Windows the two
versions are different executables (3.7.9 `CMakeLists.txt`: `AUDACITY_NAME`;
4.0.1 `src/app/CMakeLists.txt`: `Audacity4`). On macOS both have CFBundleName
"Audacity", and the Linux binary name of 4.x is not resolved, so those two get
`audacity.yaml`: only the keys both versions bind to the same action.
`org.audacityteam.audacity` is the Flatpak/AppImage app id.

## Shortcut reference

Read from the source, 2026-10-21:

- **Audacity 3.7.9** (tag `Audacity-3.7.9`), the last 3.x release: the default
  key of each command in `src/menus/*.cpp` and the other command registrations
  (`ToolsToolBar.cpp`, `Scrubbing.cpp`, `TimerRecordDialog.cpp`,
  `WaveTrackAffordanceControls.cpp`). Only the **Standard** set is drawn, the
  set a new install has: the full list minus `CommandManager::ExcludedList()`
  (`libraries/lib-menus/CommandManager.cpp`), applied while
  `/GUI/Shortcuts/FullDefaults` is false, its default. The "Extra" menu is hidden
  by default but its shortcuts work, so they are drawn.
- **Audacity 4.0.1** (tag `Audacity-4.0.1`), the current release:
  `src/app/configs/data/shortcuts.xml`, joined with the `UiAction` registrations
  and `dispatcher()->reg` handlers in `src/`. Many entries of that file are 3.x
  leftovers with no action in 4.0.1; only keys with a registered action and a
  handler are drawn.
- The Audacity manual, "Keyboard Shortcut Reference"
  (<https://manual.audacityteam.org/man/keyboard_shortcut_reference.html>), was
  compared. Where it disagrees with the 3.7.9 source (it lists Q and Ctrl+J as
  Full-set only, Redo as Ctrl+Y only, and a Zoom Tool on F4 that does not exist),
  the source is used.

macOS: Audacity maps Ctrl to Cmd and Alt to Option (3.7.9
`libraries/lib-menus/Keyboard.cpp`, `NormalizedKeyString`). For 4.0.1 the same
mapping is assumed (Qt's default); it was not checked.

Redo: 3.7.9 binds Ctrl+Y on Windows and Ctrl+Shift+Z elsewhere
(`EditMenus.cpp`, `#ifdef __WXMSW__`); 4.0.1 binds Ctrl+Shift+Z everywhere.

### Left out

- 3.7.9 Full-set-only keys (no shortcut on a new install).
- Keys that change meaning while playing: Left/Right and Shift+Left/Right also
  seek during playback in 3.7.9 (Shift+Left/Right are drawn with their selection
  meaning). Up/Down (focus track), Tab, Return in the track menu.
- 3.7.9 on macOS: Cmd+. (label at playback), Cmd+, (preferences), Cmd+/ (full
  screen) and the four Labeled Audio Alt+Shift keys exist only in the 3.x set,
  which macOS does not load.
- 4.0.1 keys whose action has no handler (Alt+F6, Alt+Shift+F6, Q, Ctrl+Shift+C)
  and the effects-panel keys (Alt+Up/Down move effect).
- Ctrl+Q (Quit). Esc: the ESC key carries the program mark.

## Icons

- Microsoft Fluent UI System Icons, MIT,
  <https://github.com/microsoft/fluentui-system-icons>. Folder names are in
  `fetch_icons.py`.
- Material Symbols, Apache-2.0, <https://fonts.google.com/icons>: every `ms:`
  entry in `fetch_icons.py`.
- New, Open, Save, Undo, Redo, Cut, Copy, Paste, Delete and Select All are drawn
  by the shared concept renderer.
