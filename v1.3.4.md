# v1.3.4 Update prompts that arrive, and round Braille

**No protocol change.** This release and firmware **1.0.0** both speak protocol 18, so either can be updated first. Update the app first if you want the round Braille dots, because the app delivers them to the keyboard.

## 1.3.4 — Braille with round dots ⠿

- **The Braille glyph script now draws round dots** instead of the square ones it had. The app reflashes that one font slot on the next connect, and it works on older firmware too.

## 1.3.1 — Firmware updates you were never told about 🔔

- **A keyboard could stay on old firmware with no prompt.** The app's first update check of a session often ran before the keyboard's version was known. It checked only for app updates, but used up the shared 6-hour limit, so the firmware check was skipped. It now keeps a separate firmware timer and checks every 6 h.
- **The ESC mark no longer flickers on windows whose title animates.** A terminal running a spinner rewrote its title every second, and each change blanked and redrew the keycaps.

## 1.3.0 — `polyctl handedness left|right` ⌨️

- **Fix a half on the wrong side from the command line.** Before, only the tray could do it, and a headless daemon has no tray. The side you name is the half the USB cable is plugged into.

## 1.3.2 — Update dialog size

The update progress dialog grew wider with every message on GNOME and macOS. It now keeps its size.

## 1.3.3 and 1.2.9 — The keymap editor catches up

The keycode list follows QMK's newer steno codes, which now sit on their own Steno tab. The keycap previews show 0.28.0's layer-key marks.
