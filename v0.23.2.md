# v0.23.2 Idle timeout control & single-instance fixes

**Protocol 17 → 18.** This release pairs with firmware **0.27.1** — update **this app first**, then the keyboard. On older firmware the new idle-timeout menu simply stays greyed out; the connection is unaffected.

## 0.23.2 — Your settings file survives a bad write

- **A malformed `settings.yaml` is no longer replaced with defaults** — it is moved aside as `settings.yaml.unreadable-<stamp>` and the app starts on defaults, so nothing is lost.
- **One tray per user**, and the two settings writers no longer overwrite each other's changes.

## 0.23.1 — Two tray icons on macOS, fixed 🍎

- **Registering autostart launched a second copy of the app.** A first-time macOS install came up with two trays: the plist carries `RunAtLoad` and `launchctl load` then started it immediately, 691 ms after the app that wrote it.
- ⚠️ **The duplicate took the keyboard with it** — it had already opened the device, and macOS makes that exclusive, so the surviving tray could never reconnect.

## 0.23.0 — Idle timeout, from the app ⏱️

How long the keycaps wait before fading is yours to set now — six presets from 15 seconds to 5 minutes, where it used to be fixed at 2 minutes inside the firmware.

- **Tray → Idle Display → Idle After**, or `polyctl idle-timeout 30sec` (also `15sec`, `45sec`, `1min`, `2min`, `5min`).
- The menu labels itself from **the seconds the keyboard reports**, so a firmware that adds a preset later reads "10 min" rather than "preset 6".
- ⚠️ **Needs firmware 0.27.1.** An older board keeps its 2-minute behaviour and the menu stays greyed out.
