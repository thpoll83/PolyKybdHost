# v0.14.18 Crash alerts & per-platform overlays

## 0.14.17 — You get told when the keyboard crashed
Firmware 0.18.2+ records a crash and announces it on its next boot. Finding that
meant reading a log by hand, so the host now watches for it.

- A crash raises an alert with two ways out: **Report on GitHub…**, which opens
  Report-a-Problem with the crash pre-filled, or **Copy to Clipboard**, which
  takes the crash plus your host diagnostics.
- `polyctl crash show [--slave] [--json] | clear` for the same thing from a
  terminal.
- **Protocol 16** — needs firmware 0.18.2+; older keyboards connect as before.

## 0.14.16 — Overlay artwork can differ per platform 🐧
The default artwork served Windows and Linux from one image, so an action that
Linux remaps had nowhere to go. Bindings now scope with `only:` / `except:` over
windows / macos / linux, and a third set is rendered when one is warranted.

- First fix from it: VS Code's **Show Output**, which is `Ctrl+Shift+U` on
  Windows but `Ctrl+K Ctrl+H` on Linux, because Ubuntu takes `Ctrl+Shift+U` for
  unicode input.

## 0.14.14 — The keycap tuner shows the held views
Mirrors the firmware's new legend layout so what you tune is what the keyboard
draws: Shift-held and AltGr-held keycap views, the four-edge clamp, the half-size
AltGr hint per layout, and the Shift-preview suppression rule shared with the
firmware rather than re-derived.

Plus maintenance releases 0.14.15 and 0.14.18 🧹
