# v1.2.8 Generic app overlays, and shortcuts on macOS

**No protocol change** — this release and firmware **0.28.0** both speak protocol 18, so the two can be updated independently and in either order. This is the 1.0 line: an application no longer needs a hand-made template to light up the keycaps.

## 1.2.6 — The forwarder's own windows
The forwarder's windows now identify themselves as PolyHost, so GNOME groups them with the tray app and the ESC program mark finds them.

## 1.2.5 — A Windows crash while reading an app's shortcuts 🪟

- **The daemon died with no log line, taking the keyboard connection with it.** The shortcut harvest cached its UI Automation object in a module global, but the harvest thread retires after 30 s idle — so the next thread called into a dead COM apartment and the process took a native fault.
- **Crash dumps are now dated and attributed**, so a log bundle says which run a fault came from instead of showing one undated pile.

## 1.2.1 — PolyHost's own windows, and the macOS Dock
- **PolyHost's own dialogs draw the PolyKybd mark on ESC**, whether or not they expose shortcuts.
- **macOS: the app becomes a regular app only while one of its windows is open**, so the Dock icon appears with the window and leaves with it.

## 1.2.0 — A mark for an app the catalogs do not know 🎨
- **Marks now ship with the app** (`res/icons/program/`) as a third source after the two online catalogs. Photos, Notes and Terminal are 404 in both under every name we can derive, so they had no mark at all.
- **The filename is the slug** — drop a PNG in for an application nobody here has heard of and it is used, with no table to edit.
- **Candidates are ranked by legibility** at 72×40 monochrome rather than first-match-wins, which is what was picking a heavy white plate for GNOME Terminal.

## 1.1.6 — Update notices that reach macOS 🍎
- **macOS never showed the "new version available" balloon** — the tray notification simply does not arrive there. It now opens a dialog instead.
- **A pending update is dropped when a later check no longer offers it**, and the fallback prompt can no longer stack two dialogs on top of each other.

## 1.1.4 — The language key works on macOS again ⌨️
- **A language key press had not changed the macOS keyboard layout since 0.18.1** — and reported success while doing nothing. The old path set the *system UI language* through a `sudo` dialog, which is a different thing and only applied at the next login.
- **It now uses Text Input Source Services** — no privileges, no password dialog, effective immediately.
- **Windows and GNOME gained the compatible-layout fallback** the KDE helper already had, so a layout the OS does not have exactly falls back instead of failing.

## 1.1.3 — An unmapped macOS function key
A function key with no HID mapping consumed its own fallback, leaving the keycap blank rather than showing the key's name.

## 1.1.0 — Shortcuts on macOS 🍎

macOS was the one platform where the generic overlays did nothing at all. Every Mac app has a real menu bar, and the Accessibility API returns a structured binding rather than a display string to parse.

- **Shortcut icons and the program mark now work on macOS**, read from the app's own menus.
- ⚠️ **Needs the Accessibility permission**, granted once per binary in System Settings → Privacy & Security → Accessibility. Without it the menu reads as empty; PolyKybd never raises the dialog itself.
- **Two untitled windows are now told apart**, and a single bad poll no longer ends window tracking for the rest of the session.

## 1.0.3 and 1.1.2 — Your settings file, preserved
An unreadable `settings.yaml` is moved aside on save, as it already was at startup, and the copy gets a name that cannot collide with an earlier one. A failed preservation stops the save rather than overwriting.

## 1.0.2 — macOS window tracking
Three fixes to the poll: a window handle is a tuple and formatting it as a number killed the whole poll; macOS reports display names and titles without the app name; and the OS-icon route was unreachable because nothing passed a pid.

## 1.0.1 — Starting the app on macOS
macOS had no way to launch PolyHost again once it was quit. It now installs a proper `.app` launcher, and never adopts or deletes one it did not write.

## 1.0.0 — Generic app overlays 🎉

An application with **no hand-made template** now gets keycap icons anyway: its own icon on ESC, and an icon per shortcut read from its accessibility tree. There is no per-application configuration — the 70-entry slug map that used to be needed is gone.

- **The app's display name is read from the file the OS already opens for its icon**, so "Microsoft Word" resolves where the executable name `winword` never could. 14 of 16 realistic names resolve with no map.
- **A bad monochrome reading is refused rather than drawn**, so a blob never reaches a keycap.
- **Four switches**, a ladder from broad to narrow: `generic_overlays_enabled`, `generic_overlays_fill_gaps` (also fill blank keys on an app that *has* a template), `shortcut_icons_enabled` (read another process at all), `shortcut_icon_auto_fetch` (fetch icons over the network).
- **The board is cleared when the next app has nothing to draw**, so stale legends do not linger.
