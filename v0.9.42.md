# v0.9.42 — Website-aware overlays

> Protocol unchanged at **v11** — pairs with firmware 0.9.68.

### Overlays can now target a website, not just a window title 🌐
Web apps all share one browser process and put inconsistent text in the window title, so Gmail, Jira, Outlook and Miro were nearly impossible to tell apart. Overlay matching can now key off the focused tab's **URL**.

- New `url` (regex) and `urls-contains` (host substring) constraints in the mapping file, checked *before* the title rules because the URL is the stronger signal. Entries without a URL behave exactly as before.
- The shipped mapping now matches **Jira, Outlook, Miro and Bitbucket by host**. This also fixes a long-standing false match where a GitHub pull request — whose title also contains "Pull Request" — triggered the Bitbucket overlay.
- Single-page apps re-match on navigation, so moving between boards or tickets switches the overlay even when the title never changes.

### A browser extension supplies the URL 🧩
A small Chromium + Firefox extension reports the active tab to the host over **loopback only** (127.0.0.1, port 50164, optional shared token), with an options page and a connection test. On macOS the scriptable browsers work with **no install at all** via an AppleScript fallback.

- Privacy-conscious by construction: the receiver is loopback-bound, has no access to device control, and debug logs record only a URL's origin — never the path or query.
- Enable or disable the whole feature with the `browser_url_detection` setting (on by default).
