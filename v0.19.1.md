# v0.19.1 Real keycaps & the WinCompose logon fix

Pairs with **PolyKybd firmware 0.23.0** (protocol 17) — update both together.

## 0.19.0 — The editor draws your actual keyboard 🖼️
- The layout editor now draws the **case outline and the board's colour**, with the keys sitting on it, instead of a bare grid on a background.
- Both **status displays are drawn at their real size**, flush to the housing, showing the whole firmware status screen — pinned to a golden fixture so the picture matches what the board renders rather than approximating it.
- The status panels **follow the layer you have selected**, through every path that can change it.

## 0.18.x — Real keycaps in the layout editor 🔍
- A **Symbol / Preview / Real** switch above the board. Every key is drawn through the firmware's own renderers, and **Real** puts the result through the same OLED simulation the font-pack inspector uses — per-pixel jitter, the cover's light-guide diffusion, the staggered grid. Both surfaces claim to show one physical panel, so they now share one preset.
- **Macro keycaps** draw their caption in the largest face whose whole run fits, truncated by measured pixel width rather than a character count — `WWWWWWWW` is exactly 72 px and `iiiiiiiiiiii` is 34, so counting characters is wrong in both directions.
- The **symbol font bundle** was reshipped with the Mayan numerals, so an untouched macro slot previews the same stock look the keyboard draws.
- The host reads the board's **state generation** out of the `GET_ID` reply, so something you change on the keyboard refreshes an open view within about a second instead of sitting stale.
- The firmware-update size limit tracks the firmware's new handedness sector, and the `.uf2` is now paired with its `.bin` by name — a release that ships three UF2s would otherwise have handed back a handedness stamp as the firmware image.

## 0.17.0 — WinCompose detection, fixed 🔤
- **At Windows logon the host lost a race with WinCompose** and pinned the keyboard to plain Windows unicode mode for the session. It watches the input method continuously now — every 10 s for ten minutes, then once a minute — instead of deciding once at startup.
- An early, ambiguous reading is applied **without storing it**: plain Windows really is how the keyboard should type while WinCompose is absent, so applying it is right, and the proper mode is re-asserted once the logon window closes. That ends the double EEPROM write and the legend flickering to where it started.
- ⚠️ The volatile half needs firmware **0.20.0 or newer** (protocol 17).

## 0.16.0 — Follows your desktop theme 🌗
- The tray menu and every dialog now take **light or dark from the OS**, with a `ui_theme` setting to override. They were unconditionally dark, which looked wrong on a light desktop.
- The **brightness icons were yellow on white** — 1.07:1 against a light menu, i.e. invisible. The whole set is re-tinted and floor-tested for contrast on both grounds, with green for automatic and amber for the dim end.
- Each entry in the **Glyph Script menu previews its own script**, drawn from the shipped font bundle, so the list reads as a comparison instead of eleven identical rows.

## 0.15.1 — A new brand mark 🎨
Redrawn as vector at much higher resolution: a keycap grid whose *unlit* keys spell a P, in a blue-to-cyan sweep, with HOST stamped out of the bottom row. The busy and warning states clear the inner keys so their glyph has room to read at 16 px.

## 0.15.0 — The taskbar knows who we are
- The Windows taskbar button showed the **Python icon**. The app never claimed an AppUserModelID, so Windows identified it by `pythonw.exe`; title bars were always correct, which is why it looked like a missing icon and was not.
- The crash dialog's **Clear** now actually forgets — it drops the host's list, the console dedupe *and* the keyboard's own flash archive, so a record from an hour ago stops riding along in every later problem report.

Plus maintenance releases 0.15.2, 0.16.1, 0.17.1 and 0.19.1 🧹
