# v0.22.0 A Windows crash fixed, twelve new app overlays & the forwarder's own tray

**No protocol change — still protocol 17**, the same as v0.19.1, so this host talks to
your existing firmware and you can update the two whenever suits you. Pairs with
**PolyKybd firmware 0.24.4**.

## 0.22.0 — The daemon stops dying on Windows 🪟
A background daemon that vanished without a trace, twice in one day, and took the
keyboard with it.

- **Reading the focused app's name went through WMI**, which opens a COM connection and
  walks *every* running process to answer one question — about 3.4 full process walks a
  minute, 48 window changes in 14 minutes of one user's log. Twice a COM proxy went away
  mid-walk (`RPC_E_DISCONNECTED`) and pywin32 dereferenced it.
- ⚠️ **The result was a Windows access violation, not a Python exception**, so the
  `try/except` around the call site could not catch it. The daemon died with **no log
  line** — both crash dumps end cut off mid-write in the window-tick thread, and neither
  wrote a clean-exit marker. "The tray icon is gone" and "the app crashed" look identical
  from the outside; this was the second.
- It now asks Windows for the **one** process it already holds a handle on
  (`QueryFullProcessImageNameW`) — no COM, no WMI, one process instead of all of them. A
  failed lookup falls back to the window title, which is exactly what the old path
  returned for an unresolvable PID, so overlay matching sees what it always saw.
- **Telemetry gained three fields** (payload schema 2): which of the three window-tracking
  backends is in use, and on Linux the session type (X11/Wayland) and desktop. Those two
  come from `XDG_*` variables, which are free text on your machine — they are mapped
  against a fixed list **before** the report is built, and anything unrecognised is sent
  as `other`, so the raw text never leaves your computer. `polyctl telemetry preview`
  shows you exactly what yours resolves to.

## 0.21.0 — Twelve more Windows apps get real keycaps ⌨️
Hand-made art per shortcut, not the generic fallback.

- **Calculator** (69 bindings, parsed out of Microsoft's own `Resources.resw` and
  `NavCategory.cs`), **Sticky Notes** (24), **Photos** (21), **Sound Recorder** (12),
  **Snipping Tool** (12), **Notepad**, **Paint**, **Paint.NET**, **WordPad**, **Task
  Manager**, **PuTTY** and **WinSCP**.
- **Sound Recorder answers to its Windows 10 name too.** Windows 11 renamed Voice
  Recorder; it is the same app with the same shortcut set, so a Windows 10 box gets the
  same keycaps rather than none.
- **Every overlay is reproducible.** A committed fetch script rebuilds the icons from
  named upstream glyphs, a per-icon transform file carries every tweak, and each glyph's
  upstream and licence is recorded — so the sources are the record rather than decoration.
- ⚠️ **A silent failure mode got a guard.** Much of the art is white on transparent, so a
  binding left on the wrong compositing mode lights the *dark* linework and renders **zero
  lit pixels** with no error from the generator. It shipped again in this batch — four
  PuTTY cells and two Paint.NET — caught only by eye. A test now reads every declared
  binding back through the real loader and fails on a cell that drew nothing.
- **Some shortcuts we had recorded as impossible are not.** Nine notes across eight apps
  still said Win-key and Ctrl+Alt+Shift combos "cannot be represented"; both have had a
  channel since protocol 12. They are now recorded as undrawn for want of art, which is a
  to-do rather than a dead end.

## 0.20.0 — The forwarder gets a tray menu worth opening 🔀
Run PolyKybdHost on a second computer and its tray menu now has the same shape as the
keyboard machine's, minus everything that needs a keyboard.

- **A status line that tells you the truth.** It reads *Forwarding to &lt;address&gt;* when
  your window reports are landing and *Cannot reach &lt;address&gt;* when they are not, and
  the tray mark greys out to match. It used to declare itself connected at startup and
  never revisit that, however long the relay had been refusing connections.
- **Pause**, for when you would rather this machine's window titles did not leave it.
  Nothing is sent while it is paused and the authenticated session is dropped; resuming
  sends the current window straight away instead of waiting for you to switch app.
- **Help & About** carries About, the log viewer, Open config folder, Report a Problem and
  Collect logs — the same set, for *this* machine's logs. That matters more than it looks:
  the forwarder runs on a different computer, so its logs can never appear in a bundle
  collected on the keyboard side.
- **Settings shows only what applies here** — the theme and the browser-URL options.
  Handing it the whole settings file would put brightness and font-pack rows on a machine
  with no keyboard, every one a control that writes a value and changes nothing.
- **The tray icon spells an F** where the keyboard machine's spells a **P**, so the two
  are distinguishable when you forward to your own desktop and both sit in one tray.

## 0.19.6 — The layout editor's previews catch up to the firmware 🖼️
Two artifacts here are generated from the firmware and had quietly fallen behind it.

- **The status-panel preview reported 39% at full brightness.** The firmware had split its
  percentage arithmetic in two — saturation really is 0..255, but the brightness value is
  capped at 100 — and this port kept the old shared helper, so a fully-lit matrix could
  never read 100.
- **The shipped preview data was stamped for an older firmware**, which is what the host
  compares when deciding whether to use the tested shipped copy or your local checkout.
  The content was already right; the stamp was sending developers down the other path.

## 0.19.2 — The layout editor header says "Layers:" again 🏷️
It had been reading "Layer:" — clipped in the app itself, not just in a screenshot of it.
The width cap that did it was redundant with the stretch factor beside it. The editor's
documentation screenshot is now generated from the real dialog, so it stops going stale
the moment the editor changes.
